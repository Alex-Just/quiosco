# Android wrapper: "Open with" for `.epub`

Android's *Open with* chooser lists apps, not PWAs. Chrome for Android ignores
the web manifest's `file_handlers` member (desktop Chromium honours it), so an
installed Quiosco cannot open an `.epub` directly from Telegram, Files, or
Downloads.

This directory is the smallest thing that can: a Trusted Web Activity generated
by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap). Chrome renders
the site, so the library, settings, and service worker are the same ones the
installed PWA uses; the APK only carries identity and intent filters. There is
no native code of our own beyond the generated launcher.

The filter it adds:

| Action | Data | Target |
| --- | --- | --- |
| `android.intent.action.VIEW` | `content://` with `application/epub+zip` | `/add` (`FILE_HANDLING_ACTION_URL`) |

The file reaches the page through `launchQueue` and is imported by the normal
Book → Add flow (see `src/components/LaunchQueueHandler.tsx`).

The APK also declares the share target, so it can replace the installed PWA.
Until the old PWA/WebAPK is removed, the share sheet may list Quiosco twice.

## Download

Every push that changes this directory rebuilds the signed APK and replaces the
asset on the rolling release:

<https://github.com/Alex-Just/quiosco/releases/latest/download/quiosco.apk>

The same release page has `SHA256SUMS.txt`. CI does this in
`.github/workflows/android-release.yml`.

## Prerequisites

- JDK 17 and an Android SDK with platform 36 and build-tools 35 or newer.
- `android/local.properties` with `sdk.dir=...` (gitignored).
- Only when regenerating: Bubblewrap configured with `bubblewrap updateConfig`.

## Build

```bash
pnpm android:build
```

Release builds are signed with `android/keystore.properties` (gitignored):

```properties
storeFile=quiosco-release.jks
storePassword=...
keyAlias=quiosco
keyPassword=...
```

Without that file Gradle still builds, but the APK is unsigned and useless for
installation. **Back up `quiosco-release.jks` and its passwords.** Losing them
means uninstalling the app and publishing a new signing certificate, which also
changes the asset links fingerprint.

`versionCode` defaults to 1 and can be raised for each distributed build:

```bash
cd android && ./gradlew assembleRelease -PversionCode=2
```

Output: `android/app/build/outputs/apk/release/app-release.apk`.

## Install

```bash
pnpm android:install          # adb install -r on the connected device
```

Or install the APK by hand. The web app must already be deployed with
`/.well-known/assetlinks.json` (see below) for file delivery to work.

## Verify

```bash
BT=~/Library/Android/sdk/build-tools/35.0.1
$BT/aapt dump badging android/app/build/outputs/apk/release/app-release.apk | head -3
$BT/aapt dump xmltree android/app/build/outputs/apk/release/app-release.apk \
  AndroidManifest.xml | grep -A14 FileHandlingActivity0
$BT/apksigner verify --print-certs \
  android/app/build/outputs/apk/release/app-release.apk
```

The package is `xyz.alexjust.quiosco`; the certificate's SHA-256 must equal the
one in `public/.well-known/assetlinks.json` and the `release` fingerprint in
`twa-manifest.json`. `src/lib/androidApp.test.ts` checks the two JSON files
agree.

## Digital Asset Links

`public/.well-known/assetlinks.json` is generated by hand from the release
certificate and deployed with the site. Chrome verifies it before handing a
file to the TWA. A wrong or missing file fails silently: the app opens, but the
`launchQueue` stays empty. Deploy the site and confirm:

```bash
curl -sS -D- https://quiosco.alex-just.workers.dev/.well-known/assetlinks.json
# Content-Type: application/json

# The same check Android performs (expect one android_app statement):
curl -sS "https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://quiosco.alex-just.workers.dev&relation=delegate_permission/common.handle_all_urls"
```

If the signing key is rotated, update both files:

```bash
npx --yes @bubblewrap/cli@1.27.0 fingerprint   # prints the statements
```

## Regenerating the project

`twa-manifest.json` records the Bubblewrap inputs. Regeneration rewrites the
project and discards the local patches in `app/build.gradle` and
`app/src/main/AndroidManifest.xml`, so reapply:

1. `jcenter()` → `mavenCentral()` in the root `build.gradle`.
2. Release signing from `keystore.properties`, `minifyEnabled false`, and the
   `lint { checkReleaseBuilds false }` block in `app/build.gradle`.
3. `android:allowBackup="false"` and removal of the deprecated `package`
   attribute in `app/src/main/AndroidManifest.xml`.

`compileSdk`/`targetSdk` 36 and `minSdk 24` come from the template and
`twa-manifest.json`. Rebuild and re-run the verification above afterwards.

## Troubleshooting on device

- **The app opens but no book appears.** File delivery needs a verified
  Digital Asset Link. Confirm the deployed file is JSON (not the SPA's HTML)
  and that the certificate matches, then ask Android to re-check:

  ```bash
  adb shell pm get-app-links xyz.alexjust.quiosco   # expect "verified"
  adb shell pm verify-app-links --re-verify xyz.alexjust.quiosco
  adb logcat | grep -iE "LauncherActivity|FileHandling|launchQueue"
  ```

- **The sender is not listed at all.** The intent filter matches
  `application/epub+zip` on a `content://` URI. A sender that labels the file
  `application/octet-stream` will not match.
- **Two Quiosco entries in the share sheet.** The installed PWA and this APK
  both register the share target. Remove the old PWA once the APK is in use;
  both use Chrome's storage for the same origin, so the library is unaffected.
